# 03-00 · 教学方案总则

> 本目录是《AI 智能体工程化项目实战》的**逐讲教学方案**（教案），共 4 个模块文件、16 讲。
> 每讲均按德国双元制**完整行动模型**（vollständige Handlung）六步组织，可直接照案授课。

---

## 1. 教案的统一结构

每讲教案包含 12 个固定栏目，便于教师快速备课与教研检查：

| 栏目 | 作用 |
|---|---|
| ① 基本信息 | 学时、地点、授课人、企业参与、教学方法 |
| ② 学习情境 | 企业真实场景描述（课堂导入用，150 字内可讲完） |
| ③ 学习目标 | 知识 3 条 / 技能 3 条 / 素养 1 条，全部可观测 |
| ④ 重点难点 | 重点 2 条、难点 2 条 + **突破策略**（不是只列难点） |
| ⑤ 行动六步时间轴 | 阶段 / 分钟 / 教师活动 / 学生活动 / 媒体，精确到 5 分钟 |
| ⑥ 问题链 | 4–6 个递进问题 + 预期回答 + 追问 |
| ⑦ 讲授提纲 | 分层要点，对应 PPT 页码 |
| ⑧ 实操任务 | 编号步骤 + 命令/代码位置 + 卡点提示 |
| ⑨ 检查表（DoD） | 学生自检 5–8 条，可勾选 |
| ⑩ 评价 | 本讲评分点、权重、评分人 |
| ⑪ 差异化 | 快班加餐 / 慢班帮扶 |
| ⑫ 作业与反思 | 课后任务 + 教师复盘提示 |

## 2. 时间轴基准（180 分钟）

| 阶段 | 分钟 | 六步 | 关键动作 |
|---|---|---|---|
| 情境唤醒 | 0–10 | 信息 | 讲场景、放事故、抛问题 |
| 目标对齐 | 10–15 | 信息 | 亮出 3+3+1 目标，说明验收标准 |
| 知识建构 | 15–55 | 信息/计划 | 概念 + 真实代码 + 反例（中间休息 10′） |
| 任务下达 | 55–65 | 计划 | 发任务书、拆解、写实施计划 |
| 方案决策 | 65–75 | 决策 | 90 秒路演 + 点评 + 定稿 |
| 实操实施 | 75–135 | 实施 | 结对编程、教师巡场、卡点记录 |
| 检查验收 | 135–160 | 检查 | DoD 自检 + 换组交叉验收 |
| 复盘评价 | 160–180 | 评价 | 复盘三问 + 打分 + 预告 |

> **弹性规则**：知识建构可压缩至 30 分钟（慢班可延至 60），压缩的时间一律补给实操；
> 检查验收不得少于 20 分钟，否则工件质量无法保证。

## 3. 复盘三问（每讲最后 10 分钟固定使用）

1. **今天做出来的东西，凭什么说它是对的？**（证据）
2. **如果它明天在生产环境坏了，最先坏在哪？**（风险）
3. **下次做同类任务，哪一步可以少走？**（沉淀）

教师记录学生回答中的高频词，作为下一讲导入素材。

## 4. 双导师协同规则

| 场景 | 学校教师 | 企业导师 |
|---|---|---|
| 企业导师主讲段 | 控场、计时、补充理论 | 讲现场、讲判据、讲踩过的坑 |
| 实操段 | 巡场答疑、记录卡点 | 只回答"现场怎么做"，不代替学生操作 |
| 评价段 | 按量表打分 | 给"能否上线"的判断与 1 条改进建议 |

**禁忌**：企业导师不评价学生"聪明与否"，只评价"这个做法在现场行不行"。

## 5. 安全与伦理前置要求

1. 第 07 讲之前，所有实操默认 `dry-run`，不得对任何真实系统执行写操作。
2. 课堂使用脱敏数据；不得把企业真实设备编号、工艺参数带出教室。
3. 任何"让模型自动执行"的演示，必须现场展示权限门拦截日志。
4. 涉及停机、备件采购的案例，只做推演，不做真实下单。

## 8. 费曼时刻操作规范（每讲 8 分钟，固定环节）

| 步骤 | 分钟 | 做法 | 教师动作 |
|---|---|---|---|
| 选题 | 0.5 | 教师读出本讲费曼题（见 §9） | 只读题，不提示答案 |
| 互讲 | 3 | 每组派 1 人 × 90 秒讲给隔壁组；禁止念 PPT，听众设定为老周 | 计时，超时打断 |
| 追问 | 2 | 每个主讲必须被追问 1 个「为什么」 | 记录答不上的点 |
| 回炉 | 2 | 讲不清/答不上的小组，翻材料 2 分钟后换人重讲 | 只补问题，不补答案 |
| 记录 | 0.5 | 把「卡壳清单」写进教师手册白板右下角 | 下一轮备课素材 |

**通过标准**：能用类比讲清 + 能接住 1 个追问 = 通过；只会背术语 = 不通过，本讲工件降一级。

## 9. 布鲁姆层级地图与费曼题库（16 讲）

| 讲次 | 主认知层级 | 费曼题（讲给老周听） |
|---|---|---|
| 01 | 理解 | 我们这门课最后交付什么？为什么不是一份报告？ |
| 02 | 应用 | 为什么「报警要及时」不能写进合同？ |
| 03 | 分析 | 为什么设备档案和诊断要分成两个上下文？ |
| 04 | 应用/分析 | 缺了一个传感器，为什么不能说设备正常？ |
| 05 | 应用 | 为什么工具不能「一个顶八个」？ |
| 06 | 分析 | 模型为什么自己停不下来？ |
| 07 | 分析/评价 | 提示词里写「禁止」，为什么不算数？ |
| 08 | 应用 | 为什么客户平台要用协议接入，而不是三套定制 API？ |
| 09 | 分析 | 未经审批的技能，为什么必须「看不见」？ |
| 10 | 应用/评价 | 一条诊断结论要带哪四样东西，班组才敢信？ |
| 11 | 分析 | 为什么预测必须给区间，而不是一个数？ |
| 12 | 评价 | 四个部门吵起来了，最后听谁的？ |
| 13 | 分析/评价 | 三层测试都绿了，系统为什么还是白屏？ |
| 14 | 应用/分析 | 断网之后，边缘系统靠什么活下去？ |
| 15 | 分析 | 出了问题，怎么在 10 分钟内定位到哪一步？ |
| 16 | 评价/创造 | 你们怎么证明这个东西值这个钱？ |

> 使用规则：费曼题**进费曼时刻才公布**——防止学生照题背稿。
> 与附录（课程标准）的认知层级保持一致；调整层级时两处同步改。
