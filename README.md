> **64 学时 · 4 学分 · 16 讲 · 16 套课件 · 全套教学文件**
> 课程载体：**谛听（Diting-PdM）设备预测性维护智能体平台** —— 雅迪电动车集团真实工程基线

## 0. 一句话说明

这不是一门"讲 AI 概念"的课，而是一门**按企业交付标准训练智能体工程能力**的课：
学生 16 讲里要交付的不是 16 份作业，而是**一个能跑、能测、能部署、能审计的智能体系统**，
每一讲产出一个可验收的工程工件（Artefakt），最后拼成完整交付物。

课程全部案例、代码、判据、事故复盘均取自开源项目 **[Diting-PdM](https://github.com/tianqiongenze/diting-pdm)**，
不虚构 Demo 数据。

## 3. 三种使用方式

### 3.1 教师：直接开课

1. 读 `00_课程总览.md`（10 分钟）→ 明确课程主线；
2. 读 `01_课程标准.md` + `02_课程授课计划.md` → 走教务处报批；
3. 按 `03_课程教学方案/` 逐讲备课，配合 `slides/pptx/第NN讲_*.pptx`（每页有讲稿备注）；
4. 打印 `09_项目任务书/` 发给学生，用 `04_考核评价与评分量表.md` 现场打分。

### 3.2 学生：按讲推进

1. 读 `08_学生手册.md` → 装环境、认领角色、建仓库；
2. 每讲课前读任务书，课中按六步法做，课后提交工件到自己的 Git 仓库；
3. 第 16 讲按 `04_考核评价与评分量表.md` 自评后答辩。

### 3.3 企业导师：只上"真"的部分

`02_课程授课计划.md` 中标注 `[企业]` 的 12 学时由企业工程师承担，配套：
- 第 02 讲：真实需求评审（带企业需求单）
- 第 10 讲：判据标定与现场误报处理
- 第 12 讲：会诊角色扮演（工艺/可靠性/生产/维修四个真实岗位）
- 第 14 讲：边缘站点接入实操
- 第 16 讲：交付答辩评委

## 4. 与上游项目的关系（重要）

本课程是 **Diting-PdM 的"教学投影"**，不是独立虚构案例。

- 上游仓库：`https://github.com/tianqiongenze/diting-pdm`（镜像 `https://gitee.com/enze_tian_qiong/diting-pdm`）
- 同步规则：**上游任何文档/代码/指标变更，必须同步到本仓库对应位置**，映射关系见 `sync/upstream-map.yaml`。
- 执行方式：

```bash
# 检查上游是否有更新（不写入）
python tools/sync_course.py --check

# 执行同步：更新 PROJECT_UPDATES.md、受影响讲次的"项目动态"区块与数据快照
python tools/sync_course.py --apply

# 同步后自检 + 重新生成受影响课件
python tools/verify_course.py
python tools/build_slides.py --changed
```

- 记录载体：`PROJECT_UPDATES.md`（只追加，不修改历史行）+ `sync/upstream-state.json`（机器可读状态）。
- 详细规则见 `AGENTS.md`。

## 5. 课程特色（为什么这样设计）

| 特色 | 具体做法 | 对应双元制要素 |
|---|---|---|
| **真项目** | 载体是已上线运行的雅迪预测性维护系统，含 146 项单测、211 项浏览器测试 | 企业真实工作任务（betrieblicher Auftrag） |
| **真标准** | 交付物按企业验收清单 42 项评审，不按"作业完整度" | 企业验收标准进课堂 |
| **真角色** | 学生分组担任项目经理/算法/后端/测试/安全/交付 6 个岗位，角色轮换 | 岗位化学习（arbeitsplatzbezogen） |
| **真约束** | 安全红线、¥5 万审批、数据不出厂、降级不崩溃——写进代码而非 PPT | 完整行动模型（vollständige Handlung） |
| **真反思** | 每讲结束 10 分钟"复盘三问"，第 16 讲做技能沉淀 | 反思性学习（reflektierendes Lernen） |
